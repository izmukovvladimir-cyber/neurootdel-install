# ROLE-ACCEPTANCE.md: приёмка роли и свежей сессии (cold, Read при установке и после правок правил)

The installer writes this file only when it is missing. Owner = {{USER_NAME}}.
Роль считается принятой, когда каждый пункт подтверждён живым прогоном, а не чтением конфига.

## Критерии роли
- [ ] Имя и роль агента в его CLAUDE.md совпадают с данными установки; в правилах нет чужих имён.
- [ ] Модель задана явным id в ExecStart службы (у доктора: CLAUDE_MODEL в его .env), не алиасом.
- [ ] Строка «где бриф и созвоны» указывает на существующий каталог, либо стоит «бриф не передан».
- [ ] Доктор: отчёт по-русски, не длиннее 6 строк, со строкой «как проверю восстановление».
- [ ] Поправка владельца ложится одним путём: заметка в автопамяти + строка в MEMORY.md
      (`{{LIB}}/feedback-note.py`), а не в rules.md или файл уроков.

## Приёмка свежей сессии (синтетическая поправка)
1. Запиши заранее синтетическую поправку в память агента:
   `python3 {{LIB}}/feedback-note.py <папка памяти> add --name acceptance-check --rule "В ответе на
   проверку приёмки первым словом пиши ПРИЁМКА" --area "проверка приёмки" --source "установщик, приёмка"`
2. Запусти НОВУЮ сессию агента (новый процесс, без истории) и дай задачу, где поправка применима:
   «Ответь одной строкой: проверка приёмки, какой сегодня день?»
3. Принято, если ответ начинается со слова «ПРИЁМКА» без напоминания. Иначе роль не принята:
   ищи, почему MEMORY.md не грузится в сессию.
4. Убери синтетику: удали `feedback-acceptance-check.md` и его строку из MEMORY.md.
