# Сверка с Codex

Порядок работы: Claude делает, Codex проверяет, Claude правит, потом отдаёт.

## Включена ли сверка
Настройки в `~/.claude-lab/shared/editorial.conf`. Пока там `EDITORIAL_ENABLED=0`, скрипт отвечает
`verdict=DISABLED` и ничего не проверяет. Тогда отдавай работу как обычно и один раз скажи владельцу:
«Сверка Codex выключена, включить: урок docs/lesson-editorial.md». Каждый раз об этом не напоминай.

## Когда
- Текст для владельца, для канала, для клиента: до отдачи.
- Решение или план (что делать, в каком порядке, сколько стоит): до того, как предложить.
- Код и скрипты: до запуска.
- Не нужно: короткие служебные ответы («принял», «делаю»), пересылка без изменений.

## Как
Промпт обязан иметь три блока: MAPPING (что читать, где лежит), ЦЕЛЬ (что проверить, одной строкой),
КОНТЕКСТ (запреты, что нельзя ломать).

```bash
~/.claude-lab/jarvis/.claude/skills/codex-check/scripts/codex-check.sh <<'P'
MAPPING: текст ниже / файл /путь/к/файлу
ЦЕЛЬ: найти ошибки в фактах, цифрах, запретах (персональные данные, кейсы без согласования), логике и тоне.
КОНТЕКСТ: кто читатель, чем пишем, откуда берутся цифры.
---
<сам текст или код>
P
```
У Кодера путь тот же, только `coder` вместо `jarvis`.

Скрипт печатает первой строкой `codex: model=<X> verdict=<APPROVE|REQUEST_CHANGES|EMPTY|CONFLICT|DISABLED>`,
дальше замечания. Вердикт считается только целой строкой `VERDICT: ...` вне блоков кода.

## Два критика для текста в канал
```bash
/usr/local/lib/<пользователь агентов>/text-critics.sh [--genre пост] [--source первоисточник.md] черновик.md [образец.md ...]
```
Редактор проверяет черновик по стандарту текста (`~/.claude-lab/shared/checklists/text-standard.md`),
корректор ищет ошибки языка. Код выхода 0 только когда оба ответили APPROVE; 2 значит отказ до вызова
модели (пустой или испорченный вход), 3 значит сверка выключена.

## Что делать с ответом
- REQUEST_CHANGES: исправь и прогони ещё раз. Не согласен с замечанием: напиши почему в отчёте.
- EMPTY, CONFLICT или ошибка: повтори один раз. Снова так же: отдай с пометкой «сверка Codex не прошла: <причина>».
- В отчёте одна строка: `Сверка Codex: <verdict>, правок <N>`.

Codex работает по подписке ChatGPT владельца, без API-ключа и без оплаты сверх подписки. У подписки есть
лимит сообщений: на пустяках сверку не гоняй.
