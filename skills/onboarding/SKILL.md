# onboarding: интервью с владельцем

Новый агент знает о владельце только имя, язык и часовой пояс из установщика. Этот скилл
превращает первые минуты переписки в знакомство: агент спрашивает сам, по одному вопросу, и
по итогу записывает профиль владельца, свою роль и правила тона.

## Когда запускать

Проверяй на ПЕРВОМ сообщении владельца в новой сессии (дёшево: три `grep`, без чтения целиком).

0. **Незаконченное интервью**: в `core/onboarding-state.md` стоит `status: in-progress`.
   Проверяется ПЕРВЫМ и независимо от признаков ниже (интервью могло начаться по просьбе при
   заполненном профиле или оборваться после записи файлов): продолжай с первого незакрытого шага.
1. **Заготовка установщика в `core/USER.md`.** Признак любой из двух:
   - строка `<!-- onboarding:installer-default -->` (её пишет установщик в новый USER.md);
   - старая установка без метки: в файле есть строка
     `- Edit this file freely -- the agent reads it on every start.` и нет ни одного раздела
     `## ` кроме `## Notes`.
2. **Нет `core/TONE_OF_VOICE.md`** (установщик его не создаёт, файл пишет только интервью).
   Для Доктора и Аудитора этот признак не считается (у них нет блока тона).
3. **Прямая просьба владельца**: «настрой меня», «познакомимся», «onboard», «перенастрой».

Перед стартом прочитай `core/onboarding-state.md`, если он есть:
- `status: in-progress` — продолжай с первого незакрытого блока, не начинай заново.
- `status: paused` — сам не начинай; не чаще раза в сутки (поле `last_offer`) одной строкой
  предложи продолжить. Просьба владельца запускает сразу.
- `status: declined` — сам больше не предлагаешь никогда, только по просьбе.
- `status: done` — признаки выше уже не сработают; запуск только по просьбе (режим дополнения).

Сначала ответь на то, с чем владелец пришёл. Интервью предлагаешь после ответа одной строкой:
«Чтобы работать под вас, мне нужно минут десять на знакомство: спрошу по одному вопросу. Начнём
сейчас или позже?». «Позже» = `paused`, «не надо» = `declined`. Срочная задача всегда важнее
интервью.

## Кто я и какие блоки спрашиваю

Роль определяешь по своему каталогу и своему `CLAUDE.md` (раздел о роли), справка по команде в
`~/.claude-lab/shared/STAFF.md`:

| Агент | Каталог | Блоки |
|---|---|---|
| Главный ассистент (тексты, контент, день владельца) | `~/.claude-lab/jarvis/` | а, б, в (полностью), г, д |
| Coder, техспец | `~/.claude-lab/coder/` | а, б, в (коротко: один вопрос), г, д |
| Доктор сервера, Аудитор | домашний каталог, `~/.hermes` | а, б, д |

Если владелец уже ответил на что-то в другом агенте и это лежит в общем доступе (например,
`~/.claude-lab/jarvis/.claude/core/USER.md` уже заполнен), не переспрашивай: покажи, что знаешь,
и спроси только «всё верно?».

## Как спрашивать

- **Один вопрос за сообщение.** Коротко, по-человечески, на языке владельца. Без анкет и
  нумерованных простыней.
- Ответ неполный или «не знаю» — принимай, иди дальше, не дави.
- После каждого ответа сразу запиши его в `core/onboarding-state.md` (см. ниже). Разговор может
  оборваться в любой момент: сброс сессии, владелец ушёл. Продолжение начинается с того места.
- «Стоп», «потом», «хватит» = `status: paused`, одна строка «Хорошо, продолжим когда скажете».
- Владелец сам рассказал больше, чем спрошено, — забери в нужные блоки, лишний вопрос не задавай.

### (а) Кто владелец
Имя и как обращаться (на «ты»/«вы», по имени, по имени-отчеству); часовой пояс и город; язык
ответов; чем занимается; продукты и цены (если есть); аудитория; каналы (соцсети, сайт, бот).

### (б) Моя роль
Что владелец ждёт именно от этого агента; три задачи, которые он отдаст первыми; чего агент
делать НЕ должен (границы: что только с его «да», куда не лезть, кому не писать).

### (в) Тон голоса
Только для главного ассистента полностью:
1. Попроси прислать 3-5 своих текстов: посты, сообщения клиентам, подписи. Можно ссылками,
   скриншотами, пересылкой.
2. Разбери их и выведи правила: средняя длина фразы и текста; обращение к читателю; эмодзи
   (есть/нет, какие, где); любимые слова и обороты; запрещённые обороты (канцелярит, клише,
   то, чего в его текстах нет); структура (абзацы, списки, призыв в конце).
3. Покажи правила списком и спроси «так?». Правки владельца вноси.
4. Спроси одним вопросом, чего в текстах от агента он НЕ терпит.

Для Coder один вопрос: «Как мне вам писать: коротко по делу или с пояснениями?».
Доктор и Аудитор блок пропускают.

### (г) Сервисы и ключи
**Пароли, токены и ключи в чат НЕ просить и НЕ принимать.** Спрашиваешь только, какие сервисы
нужны в работе (почта, календарь, платёжка, соцсети, нейросети). Для каждого, где нужен ключ,
даёшь инструкцию, как владельцу самому положить его в файл секретов на сервере:

```
mkdir -p -m 700 ~/.claude-lab/shared/secrets
touch ~/.claude-lab/shared/secrets/<сервис>-api-key
chmod 600 ~/.claude-lab/shared/secrets/<сервис>-api-key
nano ~/.claude-lab/shared/secrets/<сервис>-api-key
```

(вставить ключ одной строкой, сохранить; команды выполняются под пользователем агента). Это тот
же механизм, что у установщика: так лежит, например, `groq-api-key`. После его «положил»
проверяешь, не печатая содержимое: `test -s <файл> && stat -c '%a' <файл>` (ждёшь `600`).
Если владелец всё-таки прислал ключ в чат: не повторяй его, не сохраняй из чата, попроси
удалить сообщение и выпустить новый ключ в сервисе, потом положить его в файл как выше.

### (д) Отчёты
Как владелец хочет получать отчёты: длина (одна строка / подробно), когда (сразу / раз в день /
по вопросу), что обязательно (цифры, ссылки, что не получилось), в какое время не беспокоить.

## Прогресс: `core/onboarding-state.md`

Пиши после каждого ответа, коротко:

```
status: in-progress        # in-progress | paused | declined | done
mode: first | update       # первый проход или дополнение
started: 2026-11-07
last_offer: 2026-11-07
blocks_done: а, б
## Ответы
- а.имя: ...
- в.примеры: получено 3 из 3-5
```

Файл рабочий: после записи итога ставь `status: done`, ответы можно оставить (это не секреты).

## Итог

1. Покажи владельцу короткое резюме: кто он, что ждёт от тебя, границы, 5-8 правил тона,
   формат отчётов. В конце: «Записываю так?».
2. **Только после его «да»** записывай. Правки — вноси и покажи снова изменённое.
3. **`core/USER.md`**: перед записью копия `core/USER.md.bak-<ГГГГММДД-ЧЧММСС>-onboarding` (время в имени: копия прошлого запуска не затирается).
   - Первый проход (файл с заготовкой): метка разрешает интервью, но НЕ слепую перезапись.
     Прочитай файл целиком: всё, что в нём сверх заготовки установщика (строки, которые владелец
     дописал сам, в том числе внутри `## Notes`), перенеси в новый файл в подходящие разделы;
     если записанное расходится с ответом, покажи «было / станет» и бери ответ только по «да».
     Убрать можно только метку `<!-- onboarding:installer-default -->` и строку-заготовку
     `- Edit this file freely -- the agent reads it on every start.`. Разделы: `**Name:**`, `**Timezone:**`,
     `**Preferred language:**` (сохраняй эти три строки, их читает установщик при повторном
     запуске), дальше `## Обращение`, `## Чем занимается`, `## Продукты`, `## Аудитория`,
     `## Каналы`, `## Роль агента`, `## Границы`, `## Отчёты`, `## Сервисы`.
   - Повторный запуск (файл уже заполнен): ничего не затирать. Новое дописывать в разделы;
     если новый ответ противоречит записанному, покажи «было / станет» и меняй только по «да».
4. **`core/TONE_OF_VOICE.md`** (главный ассистент и Coder): правила тона списком, 2-3 короткие
   цитаты-образца из его текстов, раздел «Не писать так». Если файл уже есть (в любом режиме,
   в том числе в первом проходе): копия `.bak-<ГГГГММДД-ЧЧММСС>-onboarding`, прежние правила остаются,
   новые дописываются, противоречия и удаления только по «да» владельца после «было / станет».
5. **Предпочтения владельца в автопамять**: каждое устойчивое правило («не пиши длинно», «без
   эмодзи», «отчёт вечером одной строкой») — одна feedback-заметка и строка в `MEMORY.md` тем же
   путём, что и поправки владельца (`~/.claude-lab/shared/team-rules.md`, раздел «Memory»):
   ```
   python3 <lib>/feedback-note.py <memory dir> add --name <slug> --rule "..." --area "..." --source "онбординг, <дата>"
   ```
   `<lib>` и `<memory dir>` возьми из того раздела team-rules; `<memory dir>` это каталог
   автопамяти этой сессии (`~/.claude/projects/<проект>/memory`). Факты о владельце в автопамять
   не дублируй: они живут в USER.md.
6. `core/onboarding-state.md`: `status: done`. Одна строка владельцу: «Готово, записал. Поправить
   можно в любой момент словами "перенастрой профиль"».

## Чего не делать

- Не спрашивать пароли, токены, коды входа, данные карт. Ни в каком блоке.
- Не задавать два вопроса в одном сообщении и не присылать анкету списком.
- Не записывать USER.md, TONE_OF_VOICE.md и заметки без его «да» на резюме.
- Не затирать заполненный USER.md и существующий TONE_OF_VOICE.md ни в каком режиме.
- Не трогать `CLAUDE.md`, `core/rules.md`, `core/LEARNINGS.md`: интервью пишет только файлы выше.
